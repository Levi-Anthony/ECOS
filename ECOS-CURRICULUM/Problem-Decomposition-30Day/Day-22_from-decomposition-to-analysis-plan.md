# Day 22 — From Decomposition to Analysis Plan

> Week 4 · Synthesis & Communication

## Learning objective

Convert a finished structure into a **work plan**: for every branch, name the evidence it needs,
where you'd get it, the effort, and the priority — so you analyze the branches that can move the
decision, in order, instead of boiling the ocean.

## Minimum Viable Rep — 25 minutes
1. Produce the structure (an analysis plan, Template 3, for the attendance structure below).
2. Score it using the rubric.
3. Name one defect.
4. Repair one branch.
5. Write one sentence: "This structure helps because…"

## Concept lesson

A structure tells you *where* to look. An analysis plan tells you *what to look at, how, and in
what order*. Without it, a tidy tree becomes an excuse to gather everything — and you drown.

For each branch, fill five columns (Template 3): the **question it answers**, the **evidence
needed**, the **source**, the **effort** (L/M/H), and the **priority**. Priority is the judgment
move: it's set by *decision-relevance × cheapness*, not by curiosity. A branch is high-priority
when (a) resolving it would change the recommendation **and** (b) the evidence is cheap to get.
A branch that's fascinating but couldn't change what you'd do is a low priority no matter how
easy it is — and a branch that could change everything but costs a month of work gets a smaller,
faster proxy test first.

The plan's real output is **sequence**: the one or two analyses you run *first* because they have
the highest chance of resolving the question per hour spent. This is the hypothesis-tree instinct
(Day 15) applied to evidence — test the load-bearing claim before decorating the rest.

A good plan is also honest about what you *can't* measure. Mark those branches "estimate /
label assumption," not "unknown so ignore." Day 28 will hold you to a verdict on every branch.

## Practice case

Decision-maker: **you, deciding the studio's next operating move on the 6pm beginner class.** The
Week-3 spine gave you this structure for *why 6pm attendance is inconsistent*:

```
├── Top-of-funnel: too few people ever try the 6pm slot
├── Conversion: triers don't return for a second class
├── Schedule fit: 6pm collides with commute / dinner for the target segment
└── In-room experience: energy/level mismatch drives drop-off
```

You have **two weeks and no budget for a survey vendor** before the term schedule locks — so
"just gather more data" isn't available. Build the analysis plan that decides which branch you
actually investigate first.

## Deliverable + Definition of Done

A filled Template 3 table — every branch with question, evidence, source, effort, priority — plus
a one-line **sequence statement**: "I run ___ first because it's the cheapest test that could
flip the recommendation."

**Definition of Done:** priorities are justified by decision-relevance × cost, not interest; at
least one branch is marked "estimate/assumption" rather than dropped; and the plan names the
**next irreversible action it sets up** — locking the term schedule around a slot decision, which
you can't quietly reverse mid-term without confusing students.

## Self-check rubric

- [ ] Every branch has all five columns filled (no blanks hand-waved away).
- [ ] Priorities reflect decision-relevance × cheapness, not which branch interests me.
- [ ] I named the *first* analysis to run and why it's first.
- [ ] At least one un-measurable branch is labeled "estimate," not silently dropped.
- [ ] **What evidence, example, or counterexample would show this is incomplete, overlapping, or decision-irrelevant?** (e.g., the high-priority branch turns out not to change the decision.)
- [ ] I can name the irreversible action this plan sets up.

## Common mistake to watch for

**Equal-weighting every branch.** Beginners plan to investigate all four branches equally and run
out of time before any is resolved. The plan exists to make you *unequal* on purpose — front-load
the branch most likely to decide the question.

## When to use / when NOT to use

**Use** an analysis plan any time a structure will drive real work and your time is bounded —
which is always. **Don't** over-engineer it for a five-minute problem; if you can answer the
question by glancing at the sign-in sheet, skip the table and look.

## Reflection question

Which branch did you *want* to investigate first — and was it the one most likely to change the
decision, or just the most interesting to you? The gap between those is where time gets wasted.

## Optional stretch

Build a Template-3 plan for a live problem of your own (Case Bank 11 or 15). Then estimate hours
per branch and see whether your stated priority survives contact with the real effort numbers.
