# Capstone — The Brief

The capstone (Days 27–29, reviewed Day 30) is where everything comes together: receive an
ambiguous problem, *choose and justify* a structure, analyze it, and deliver a concise
consulting-style recommendation. This file is your brief, deliverable spec, model outline,
and rubric.

---

## The brief

Pick **one** problem you genuinely care about. Best sources:
- A real, currently-open problem from your life (strongest — you'll actually use the output).
- A multi-lens case from `Case-Bank.md` (cases 1, 11, or 16 are rich enough).

It must be **ambiguous** — no obvious single answer, no pre-chosen structure. If you already
know the answer, it's too easy for a capstone; pick something genuinely unresolved.

Write the problem as a one-paragraph situation, as a colleague would hand it to you. Include
what's known, what's uncertain, and what decision hangs on it.

---

## Day 27 — Structure (pt.1)

**Deliverable:** a chosen structure + a justification.
1. Run the Day-21 diagnostic questions on your problem.
2. **Name the lens (or sequence of lenses) you'll use, and write 3–4 sentences on *why*** —
   and why you rejected the obvious alternative.
3. Build the structure using the matching template from `Templates.md`.
4. Run the §8 master checklist on it.

**Definition of Done:** a structure that passes the checklist, plus a written justification
that names at least one rejected alternative.

---

## Day 28 — Analyze & synthesize (pt.2)

**Deliverable:** an analysis plan + findings + a governing message.
1. Turn the structure into an analysis plan (Template 3): what evidence each branch needs.
2. Gather what you can (real data if available; clearly-labeled estimates if not — state
   every assumption).
3. Synthesize: what's the single governing message the findings add up to? (Pyramid: one
   message, 3 supports.)

**Definition of Done:** every branch has an evidence verdict (confirmed / refuted / unknown),
and you've written one governing-message sentence.

---

## Day 29 — The report (pt.3)

**Deliverable:** a one-page consulting-style report.
- **Executive summary** (Template 6): SCQA + answer-first recommendation.
- **Supporting structure:** the trimmed tree/map showing how you got there.
- **Action titles:** every section heading is a complete-sentence claim.
- **Risks / what would have to be true:** 2–3 honest caveats (from Day 26).

**Definition of Done:** a reader who sees only the first paragraph still gets your
recommendation and the top reason for it.

---

## Model-answer outline (compare, don't copy)

```
EXEC SUMMARY
  Situation: [stable context]
  Complication: [what changed]
  Question: [the decision]
  Recommendation: [one sentence, answer-first]
  Because: (1) ___  (2) ___  (3) ___

HOW WE GOT HERE
  Lens chosen: [X], because [reason]; rejected [Y] because [reason].
  Structure: [trimmed tree / map]
  Key findings per branch: [...]

RISKS / WHAT WOULD HAVE TO BE TRUE
  - [assumption 1] — and how I'd test it
  - [assumption 2]

NEXT STEP
  [the single concrete action you're recommending]
```

## Capstone rubric (self-score 1–3)

| Criterion | Looking for |
|---|---|
| **Lens choice** | A deliberate, justified lens — not a reflexive MECE tree |
| **Structure quality** | Passes the master checklist; cut at the right grain |
| **Decision-relevance** | Every branch could change the recommendation |
| **Evidence discipline** | Assumptions stated; branches have verdicts; disconfirming evidence sought |
| **Synthesis** | Findings roll up to ONE governing message, not a data dump |
| **Communication** | Answer-first; action titles; readable in one page |
| **Honesty** | Real risks and "what would have to be true" named |

**Pass bar:** mostly 2–3, with *Lens choice* and *Synthesis* at 2+. These two separate
"structured thinking" from "made a tidy diagram."
