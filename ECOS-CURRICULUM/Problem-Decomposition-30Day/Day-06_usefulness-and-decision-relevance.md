# Day 6 — Beyond MECE: Usefulness & Decision-Relevance

> Week 1 · Foundations

## Learning objective

Judge a structure by whether it changes a decision — and prune the branches that don't.

## Minimum Viable Rep — 25 minutes
1. Produce the structure (prune the bushy tree below).
2. Score it using the rubric.
3. Name one defect.
4. Repair one branch.
5. Write one sentence: "This structure helps because…"

## Concept lesson

Here's the trap that catches careful people: a structure can be flawlessly MECE — no overlaps,
no gaps, beautifully symmetric — and still **useless**. MECE is a *hygiene* check, not a value
check. A tree of "all the marketing channels that exist" can be perfectly MECE and change no
decision if marketing isn't your problem.

The test that separates useful from tidy is the **"so what?"**: for each branch, ask *"If I
learned the answer here, would I do anything differently?"* If the honest answer is no, the
branch is decoration — prune it. The branches that survive are the ones worth your analysis
time.

This is why you choose the cut to serve the **question**, not the other way around. Start from
the decision you face, and let it pull the structure into shape. A useful tree is lopsided: it
drills deep where decisions live and stays shallow everywhere else. Symmetry is a sign you
structured for neatness, not for the decision.

## Practice case

Below is a deliberately bushy, over-symmetric tree for **"How do we grow studio revenue?"** —
every branch expanded to equal depth: pricing, channels, retention, referrals, new programs,
partnerships, events, merchandise, online. Prune it: keep only the branches that, if resolved,
would change what you'd actually do next quarter. Justify each cut.

## Deliverable + Definition of Done

A pruned tree plus a one-line "so what?" justification for each surviving branch (and a note on
what you cut and why).

**Definition of Done:** every surviving branch passes the "would this change a decision?" test;
the tree is visibly lopsided toward where decisions live; and you've named the one branch most
likely to change your next move.

## Self-check rubric

- [ ] I cut every branch that wouldn't change a decision.
- [ ] Each surviving branch has a "so what?" that names a possible action.
- [ ] The pruned tree is lopsided toward the real decision, not symmetric.
- [ ] **Which surviving branch is still tidy-but-low-value — and what evidence shows it's
      decision-irrelevant?** (Cut it or defend it.)
- [ ] I named the branch most likely to change my next move.

## Common mistake to watch for

Keeping a branch because it's *interesting* or *true*, not because it's *decision-relevant*. "We
could sell merchandise" may be true and tidy and still irrelevant to this quarter's growth
decision. Interesting ≠ useful.

## When to use / when NOT to use

**Use** the "so what?" prune on every structure before you invest in analysis. **Don't** prune
so aggressively that you cut a branch just because it's *hard* to investigate — relevance, not
convenience, is the cut criterion.

## Reflection question

When you build structures, do you tend to over-expand (everything gets equal depth) or
over-prune (you drop branches that are inconvenient)? Name your bias.

## Optional stretch

Take a real plan you're working from — a project plan, a class outline — and run the "so what?"
prune on it. How much of it survives a strict decision-relevance test?
