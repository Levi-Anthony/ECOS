# Lens-Selection Cheat Sheet

> One page. Print it. This is the single most valuable artifact in the program — it turns
> "which structure should I use?" from a stare-at-the-wall moment into a 30-second diagnostic.
> You get it on Day 1 as a reference, annotate it through Week 3, and personalize it on Day 30.

---

## The 30-second diagnostic

Ask these in order. The first strong "yes" usually names your lens.

1. **Am I choosing among options?** → **Decision tree** (or 2×2 if no real uncertainty).
2. **Is it a vicious/virtuous cycle — everything feeds back?** → **Causal-loop map.**
3. **Does it break somewhere in a sequence?** → **Process map / funnel.**
4. **Do I have a hunch and little time?** → **Hypothesis tree.**
5. **Is it a number that moved?** → **Algebraic / driver tree.**
6. **Do different groups behave differently?** → **Segmentation.**
7. **Do people's choices drive it?** → **Stakeholder / incentive map.**
8. **None of the above — I just need full, no-blind-spot coverage?** → **MECE issue tree.**
9. **Brand-new problem, borrowed categories feel wrong?** → **First-principles**, then re-ask.

## Symptom → lens (quick lookup)

| If the problem sounds like… | Use |
|---|---|
| "Should we do A or B?" | Decision tree |
| "It's a downward spiral" | Causal-loop map |
| "We lose people between step X and Y" | Process map / funnel |
| "I bet the cause is ___" | Hypothesis tree |
| "Profit / signups / hours are down" | Driver tree |
| "Beginners churn but regulars don't" | Segmentation |
| "It depends what the board/clients decide" | Stakeholder map |
| "Make sure we didn't miss anything" | MECE issue tree |
| "We've never faced this before" | First principles |

---

## When NOT to use each (the discipline half)

| Lens | Do NOT use when… |
|---|---|
| MECE issue tree | causes are interdependent or feed back — the clean boxes will lie |
| Hypothesis tree | you have no hunch yet, or you'd ignore disconfirming evidence |
| Decision tree | there's no real choice, or payoffs/probabilities are pure fantasy |
| Causal-loop map | the system is genuinely linear — you're adding complexity for show |
| Process map | the problem isn't sequential (it's about *who* or *which*, not *where*) |
| Segmentation | the groups behave the same — you're slicing for no reason |
| Driver tree | the metric's drivers interact non-additively |
| First principles | a proven framework already fits — don't reinvent the wheel under time pressure |

---

## The move most people miss: sequencing lenses

Hard problems rarely take one lens. Strong analysts **start broad, then switch:**

- *Process map → causal loop:* find where it breaks, then ask if the breakage is
  self-reinforcing.
- *Hypothesis tree → driver tree:* guess the cause, then quantify it.
- *Issue tree → decision tree:* map the space, then choose within it.
- *Segmentation → first principles:* find the odd group, then rebuild why it's different.

If two lenses both seem plausible, that's not a failure — name both and say which you'd run
first and what result would make you switch.
