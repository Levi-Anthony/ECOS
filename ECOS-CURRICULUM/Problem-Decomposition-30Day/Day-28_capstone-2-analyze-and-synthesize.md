# Day 28 — Capstone pt.2: Analyze & Synthesize

> Week 4 · Capstone

## Learning objective

Turn yesterday's capstone structure into an **analysis plan**, gather what evidence you can
(labeling every assumption), give **every branch a verdict** — confirmed / refuted / unknown — and
roll the verdicts up into **one governing-message sentence.** This is Day 28 of the brief in
`Capstone.md`; work that file as your spec.

## Minimum Viable Rep — 25 minutes
1. Produce the structure (the analysis plan + branch verdicts + governing message for your capstone).
2. Score it using the rubric.
3. Name one defect.
4. Repair one branch.
5. Write one sentence: "This structure helps because…"

## Concept lesson

Yesterday you built a structure; today you make it *earn its keep*. Two moves chained:

**Plan, then verdict.** Convert the structure into an **analysis plan** (Template 3): for each
branch, the question it answers, the evidence needed, the source, the effort, and the priority
(Day 22 — decision-relevance × cheapness, not curiosity). Then gather: real data where you have it,
**clearly-labeled estimates where you don't** — never silent guesses. The discipline that separates
analysis from hand-waving is that **every branch ends with a verdict**: *confirmed* (evidence
supports it), *refuted* (evidence kills it), or *unknown* (couldn't resolve — and you say so out
loud). "Unknown" is an honest verdict; a blank is not.

**Synthesize.** Verdicts are still facts. The capstone demands you **roll them up into ONE
governing message** (Day 23 / Minto pyramid): the single sentence the verdicts add up to, with the
confirmed/refuted branches as its support. The test is the same: could a reasonable person disagree
with your top line? If it survives deleting every branch beneath it and still says something
decision-shaped, you've synthesized. If it collapses into "here's what we found," you've stacked —
and the capstone rubric will flag it, because *synthesis* is one of the two criteria that separate
structured thinking from a tidy diagram.

## Practice case

Decision-maker: **you, plus whoever receives tomorrow's recommendation** (board, client,
yourself). Take the capstone structure you built and justified on Day 27 and run it through to a
governing message. Use real evidence from your domain where it exists.

The trap and the constraint: you will *not* have clean data on every branch — this is a real,
ambiguous problem. The cowardly move is to mark the hard branches "needs more research" and stall.
The brief forbids it: **label the assumption, give the branch a verdict (often "unknown — here's
what would resolve it"), and synthesize anyway.** Tomorrow's report has to land on a recommendation;
an all-"unknown" analysis is a refusal to decide, not rigor.

## Deliverable + Definition of Done

Per the `Capstone.md` Day-28 spec: a Template-3 analysis plan, gathered evidence with every
assumption labeled, a verdict on **every** branch (confirmed / refuted / unknown), and one
governing-message sentence.

**Definition of Done:** no branch is left without a verdict; every estimate is labeled as such; the
governing message is a single disagreeable claim, not a recap; and the message points at the
**irreversible/reputation-sensitive action** tomorrow's report will recommend — so the synthesis
is aimed at a decision someone will actually have to make and be accountable for.

## Self-check rubric

- [ ] Every branch has a verdict: confirmed, refuted, or unknown — no blanks.
- [ ] Every estimate or assumption is explicitly labeled, not slipped in as fact.
- [ ] Priorities in the plan reflect decision-relevance × cost (Day 22), not interest.
- [ ] My governing message is ONE sentence a reasonable person could disagree with.
- [ ] **What evidence, example, or counterexample would show this is incomplete, overlapping, or decision-irrelevant?** (e.g., a refuted branch that actually contradicts my top line.)
- [ ] I can name the irreversible action the governing message points toward.

## Common mistake to watch for

**The "unknown" cop-out as a wall.** Marking branches unknown and then *stopping* — treating
uncertainty as permission not to conclude. Unknown is a verdict, not an exit: each one must carry
*what would resolve it*, and you still synthesize the knowns into a message. A report that says
"we need more data on everything" failed Day 24's standard before it began.

## When to use / when NOT to use

**Use** this plan-verdict-synthesize chain whenever a structure has to produce a defensible
conclusion under real time and data limits. **Don't** over-formalize it for a problem you can
resolve by looking once — but on a capstone-grade decision, the verdict discipline is what keeps
you honest.

## Reflection question

Which branch were you tempted to leave blank or soften to "needs research"? That's usually the
load-bearing one — the branch whose verdict would most move the recommendation, which is exactly
why it felt safer to avoid.

## Optional stretch

Before writing the governing message, write the *opposite* message — the conclusion you'd reach if
your two strongest branches were refuted. If the opposite is plausible, your synthesis is a real
claim; if it's absurd, your structure may have been aimed at a foregone conclusion.
