# Day 18 — Process Map vs. Causal/Driver Analysis

> Week 3 · Lens Selection & Sequencing · *load-bearing*

## Learning objective

Run the *same* problem through a process map and a causal/driver analysis, and articulate
exactly what each lens reveals and what it hides — including cause vs. symptom and the
correlation ≠ causation trap.

## Minimum Viable Rep — 25 minutes
1. Produce the structure (both a process map and a driver/causal sketch of the spine case).
2. Score it using the rubric.
3. Name one defect.
4. Repair one branch.
5. Write one sentence: "This structure helps because…"

## Concept lesson

A **process map** lays the problem out as a sequence — *awareness → inquiry → first visit →
return → regular* — and asks *where* the flow leaks. A **causal/driver analysis** asks *why* a
number moves and whether one thing actually *causes* another, guarding against two errors:
mistaking a **symptom** for a **cause** (buying more bandwidth when the real cause is an
unowned backup schedule), and mistaking **correlation** for **causation** (attendance dips on
rainy days — is it the rain, or the season the rain comes in?).

Neither lens is "right." The process map *localizes* — it tells you which step is leaking. The
causal/driver lens *explains* — it tells you why that step leaks and whether fixing it will
actually move the outcome. The strong move is to **sequence them**: map the process to find the
leaky step, then run causal analysis *on that step* to find the real driver. Running causal
analysis on the whole blurry problem wastes effort; running it on a localized step is surgical.

## Practice case — the Week-3 spine

**ECTango attendance is inconsistent.** Beginner attendance is up after social posts, but repeat
attendance is down; advanced dancers say class energy is lower; the venue wants a predictable
weekly headcount; Levi suspects curriculum sequencing, instructors blame schedule fatigue.

Today: (a) build a **process map** of the attendance journey and mark where the biggest leak
is; (b) take that leaking step and build a small **driver/causal analysis** of it — list
candidate causes, separate symptom from cause, and flag any "cause" that's really just a
correlation. Then write what each lens showed that the other couldn't.

## Deliverable + Definition of Done

A process map (with the leak identified) + a causal/driver analysis of the leaking step + a
2–3 sentence "reveals/hides" comparison.

**Definition of Done:** the process map localizes a specific leak; the causal analysis on that
step distinguishes at least one symptom from a real cause and flags one correlation-not-cause
risk; and you can name the intervention this sequence points to — **the decision it improves.**

## Self-check rubric

- [ ] My process map is a real sequence with a clearly identified leak.
- [ ] My causal analysis separates at least one symptom from an underlying cause.
- [ ] I flagged at least one "cause" that might be correlation, not causation.
- [ ] **What evidence would show my identified leak or root cause is wrong?** (Name the test.)
- [ ] I stated what the process map revealed that the causal lens hid, and vice versa.

## Common mistake to watch for

Treating the *first step that looks bad* as the root cause. The process map finds *where*; it
does not tell you *why*. Skipping the causal step means you "fix" a symptom — e.g., pumping more
beginners into the top of a funnel that leaks at the second visit.

## When to use / when NOT to use

**Use** a process map when the problem lives in a sequence; **use** causal/driver analysis when
you need to know whether a fix will actually move the outcome. **Don't** run causal analysis on
the whole fuzzy problem before localizing — and don't trust a correlation as a cause without a
disconfirming test.

## Reflection question

Did the process map move your suspicion away from where you started (curriculum? fatigue?)? Often
localizing the leak relocates the real question entirely.
