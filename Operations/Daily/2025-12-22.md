# Key Takeaways / Action Map

## Core Principles / Decisions
- Reality-Weighted Effort: “If it doesn’t touch reality soon, it’s rehearsal, not work.”
- Parity Rule locked in: **No think without do.** Design must be paired with real-world reps.
- WIP constraint accepted in principle: fewer active arenas/projects, more depth per lane.
- Tools/prompts are servants, not a constitutional project: complexity must be justified by load.
- Invariant Core reframed as a **salience activation switch**, not a perfection project.

---

## Operational Rules (Agreed-in-Spirit)

- **Parity Rule (Design ↔ Rep)**
  - For each meaningful design block (max 30–60 min), you owe at least one concrete rep:
    - e.g., class actually run, landing page published, email/text sent, drill tested live.

- **Scarcity Rule (Projects ↔ Attention)**
  - Max ~3 active arenas.
  - Max ~2 active projects per arena (≈6 projects total).
  - New project only enters if:
    - There’s an open slot, **and**
    - It materially impacts income/authority/simplification in 4–8 weeks.

- **Tool Rule (Complexity ↔ Load)**
  - No refining a tool/prompt/system until it has helped ship **≥3 real outputs**.
  - Prompt “ecosystem” = global profile + per-project context note + 90-sec session recap.

- **Resolution Rule (Processing ↔ Decision)**
  - Emotional / cognitive processing must end in:
    - a concrete message,
    - a policy / written decision,
    - or an explicit “no further action for now” – not endless rumination.

- **Invariant Core as Switch**
  - Short, speakable 2–3 line Core used as:
    - a daily and pre-event salience switch,
    - always tied to one embodiment move in the next hour.

## Concrete Action Items (Near-Term)

- Parity Rule Implementation
  - [ ] Write the Parity Rule in one place you see often: “No think without do.”
  - [ ] Before the next “design session,” fill in:
        - What am I designing?
        - Why this month?
        - What concrete rep will this feed **today**?
  - [ ] Use a timer: stop design at 30–60 minutes and *immediately* do the paired rep.

- WIP / Project Limits
  - [ ] List current arenas and projects, then explicitly choose:
        - Up to 3 active arenas.
        - Up to 2 active projects per arena.
  - [ ] Move everything else into a “Later / Parked” section with a one-line “unfreeze” condition.

- Per-Project Context Notes
  - [ ] For each active project, create a simple note with:
        - Purpose (1–3 lines)
        - Current state
        - Decisions so far
        - Active questions
        - Next 2–3 concrete tasks

- Daily / Weekly Rituals
  - [ ] Daily: pick **one design → rep pair** and do both sides.
  - [ ] Weekly (10–20 min): review active projects and:
        - Park anything that hasn’t moved in 2+ weeks.
        - Retro-pair any “unpaired design” or archive it as such.

- Invariant Core as Salience Switch
  - [ ] Draft a compact 2–3 line Core you can read in <15 seconds.
  - [ ] Define triggers to read it (morning, pre-class, pre-hard-message).
  - [ ] Each activation: ask “What’s one move that embodies this in the next hour?” and do it.

## Guardrails / Anti-Patterns to Watch

- [ ] Don’t turn the Parity Rule into a massive framework; it lives on **one page max**.
- [ ] Don’t grow project count without explicitly parking something else.
- [ ] Don’t keep refining tools/prompts that haven’t yet been used under real load.
- [ ] Don’t use the Invariant Core as an override to avoid feeling; use it *after* you name the feeling.
